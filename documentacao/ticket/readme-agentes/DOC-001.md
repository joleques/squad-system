# Documentar o uso prático da squad e de seus agentes

## Objetivo

Tornar o README um guia prático para operar a Squad de Chão de Fábrica, explicando como iniciar uma demanda, o papel de cada agente, as etapas do workflow e as interações esperadas do usuário até a conclusão.

## Contexto

O README atual cobre instalação, diagnóstico, remoção, arquitetura e publicação, mas não orienta de forma suficiente a operação cotidiana dos quatro agentes. As fontes canônicas para essa documentação são o contrato em `AGENTS.md` e os papéis em `.agent/subagents/`.

## Escopo

- Atualizar `README.md` com instruções práticas para iniciar e acompanhar demandas pela squad.
- Detalhar responsabilidades, limites e entregas de `service-lider`, `service-analista`, `service-dev` e `service-reviewer`.
- Documentar o workflow completo, incluindo classificação, plano, aprovação explícita, testes iniciais, implementação, revisão, validação do usuário, ajustes e conclusão.
- Explicar o que o usuário precisa fornecer ou decidir em cada gate.
- Explicar a função do diretório `documentacao/`, onde ficam registrados os trabalhos realizados e como esse acervo pode apoiar pesquisas históricas sobre mudanças do projeto.
- Preservar as instruções existentes de instalação, diagnóstico, desinstalação, arquitetura e publicação.
- Adaptar `tests/distribution.test.js` para proteger a presença dos elementos essenciais do novo guia.

Fora de escopo:

- Alterar o comportamento da CLI, os contratos dos agentes ou o fluxo operacional.
- Modificar as fontes canônicas dos papéis.
- Introduzir novas ferramentas, papéis ou etapas na squad.

## Definition of Done

- [ ] O README apresenta uma jornada prática completa, da abertura da demanda ao aceite final.
- [ ] Os quatro papéis possuem responsabilidades, limites e resultados esperados descritos de modo consistente com as fontes canônicas.
- [ ] Os gates de aprovação do plano, testes, revisão técnica e validação do usuário estão explícitos.
- [ ] A continuidade de ajustes pontuais e a abertura de nova demanda para objetivo independente estão documentadas.
- [ ] Exemplos práticos mostram como o usuário aciona e responde à squad sem depender de comandos internos de subagentes.
- [ ] O README identifica `documentacao/` como o local de registro dos trabalhos e orienta seu uso como fonte de pesquisa histórica das mudanças.
- [ ] As seções existentes do README permanecem corretas e utilizáveis.
- [ ] Testes automatizados protegem o contrato documental essencial e a suíte `npm test` passa.
- [ ] A revisão técnica confirma aderência ao ticket e às fontes canônicas.

## Critérios de Aceite

- Dado um usuário que acabou de instalar a squad, quando consultar o README, então consegue identificar que deve conversar com o agente atual e descrever sua demanda ao `service-lider`.
- Dada qualquer etapa do workflow, quando o usuário consultar o guia, então identifica o papel responsável, o que ele está fazendo e se existe alguma ação ou decisão pendente do usuário.
- Dada uma demanda de implementação, quando o fluxo for descrito, então a primeira alteração ocorre somente após plano e aprovação explícita, seguida do gate inicial de testes.
- Dada uma revisão aprovada, quando o workflow for consultado, então o status seguinte é `aguardando-validacao`, e a conclusão depende de aceite explícito do usuário.
- Dado um ajuste pontual durante a validação, quando o guia for consultado, então ele permanece no mesmo ticket e retorna a dev/reviewer sem nova triagem ou aprovação do plano.
- Dado um novo objetivo independente, quando o guia for consultado, então fica claro que uma nova demanda deve ser aberta.
- Dado um usuário que queira entender mudanças anteriores, quando consultar o README, então identifica o diretório `documentacao/` como acervo dos trabalhos realizados e sabe que pode pesquisá-lo como histórico do projeto.
- Dada a execução de `npm test`, quando o README contiver o guia aprovado, então os testes de distribuição validam seus marcadores essenciais sem exigir redação literal integral.

## Impacto

- Documentação pública: amplia o README, reorganiza a orientação de uso e torna explícito o papel do acervo em `documentacao/`.
- Testes: estende o contrato documental em `tests/distribution.test.js`.
- Código, CLI, arquitetura e contratos instalados: sem alteração esperada.
- Risco principal: divergência futura entre README e fontes canônicas; mitigado por referência explícita às fontes e asserções focadas nos invariantes do fluxo.

## Plano de Implementação

1. Executar `npm test` antes de editar e interromper se houver falha preexistente.
2. Acrescentar ao `README.md` uma seção de operação prática com ponto de entrada, responsabilidades dos quatro papéis, workflow ponta a ponta, gates, estados, exemplos de interação e orientação sobre `documentacao/` como registro e fonte de pesquisa histórica.
3. Criar primeiro as asserções do contrato documental em `tests/distribution.test.js` e confirmar que falham sem o novo conteúdo.
4. Ajustar o README até atender aos critérios, preservando e integrando as seções existentes.
5. Executar os testes relevantes e depois `npm test`.
6. Submeter a alteração ao `service-reviewer` para conferir aderência, consistência com as fontes canônicas e qualidade dos testes.

## Lacunas Bloqueantes

Nenhuma. A terminologia e o fluxo estão definidos nas fontes canônicas do repositório.
